# 「二次創作」重繪戶型圖：法律分析與阿陞版標準戶型示意圖

日期：2026-11-04　｜　對象：林津陞（全國不動產板橋加盟店）／banqiaoasheng.com
性質：研究整理，**不是律師意見**；標「未查證」的是沒有找到原文或判決可以核對的部分。

---

## 一句話結論

**把建商圖、591 或他店的格局圖拿來描、套底、掃描後換顏色和線條粗細，法律上大多會被認定是「重製」，頂多算「改作」，兩種都要對方授權。所以不能當成「二次創作」繞過去。**
可以做的是**不看原圖、只用事實資料自己畫**的「標準化示意圖」：房廳衛數、權狀面積、方位、自己到現場看到的房間相鄰關係，再套統一的阿陞版樣式。這樣出來的是阿陞自己的著作，風險低。

「格局是事實」這句話**只對了一半**。「三房兩廳、主臥在東南角、客廳連前陽台」是事實或概念，不受保護（著作權法第10條之1）。但一張平面圖上的牆線位置與比例、房間形狀、家具與符號、標註文字、構圖取捨，屬於「表達」，受保護。改顏色和線條粗細，碰到的只是最表面的樣式，表達的骨架（幾何與比例）完全沒變。

## 任務一：法律分析

### 1. 條文（全國法規資料庫，著作權法 https://law.moj.gov.tw/LawClass/LawAll.aspx?pcode=J0070017 ）

| 條文 | 內容（節錄） | 跟這件事的關係 |
|---|---|---|
| 第3條第1項第5款 重製 | 「以印刷、複印、錄音、錄影、攝影、筆錄或其他方法直接、間接、永久或暫時之重複製作」；依建築設計圖建造建築物也算 | 描圖、掃描、AI 照著畫，都是「其他方法」的重複製作 |
| 第3條第1項第11款 改作 | 「以翻譯、編曲、改寫、拍攝影片或其他方法就原著作另為創作」 | 要加入**新的創作**才算改作 |
| 第6條 衍生著作 | 改作的成果以獨立著作保護，但「對原著作之著作權不生影響」 | 就算重繪後自己有著作權，也不會因此取得使用原圖的權利 |
| 第10條之1 | 保護只及於表達，不及於思想、概念、原理、發現等 | 房廳衛數、相對位置、坪數是事實或概念，可以自由使用 |
| 第22條第1項 | 著作人專有重製權 | 重製要授權 |
| 第28條 | 著作人專有改作成衍生著作的權利 | 改作**也要授權**，所以就算主張是改作也沒用 |
| 第52條 | 為報導、評論、教學、研究等正當目的之必要，在合理範圍內可以引用 | 社區頁屬於招攬生意，整張圖重畫很難說是「必要的引用」 |
| 第65條第2項 | 合理使用要看四個基準：目的（是否商業）、著作性質、利用的質量與比例、對原著作市場的影響 | 商業目的、整張利用，對四個基準都不利 |

其他相關：上網屬於公開傳輸（第26條之1）；民事賠償如果損害難以證明，法院可以酌定 1 萬到 100 萬元（第88條第3項）；另外有刑責（第91條以下）。這些條號依條文結構記載，**本次沒有逐條核對原文**。

### 2. 「描完換顏色、換線條粗細」到底算什麼

**(a) 智慧局的見解：只是小幅修改 → 重製；加入新創意 → 改作；兩種都要授權。**
- 智慧局著作權 Q&A〈參考網路照片繪製的作品，拿去販售會侵害著作權嗎?〉指出「通常將照片改為圖畫，表現方法有別，屬改作的利用行為」，「改作權屬於著作財產權人所專有」，除符合第44至65條合理使用外「應取得著作財產權人同意或授權」，而且拿去商業利用「主張合理使用的空間較小」。https://www.tipo.gov.tw/tw/copyright/774-5057.html （已開啟核對）
- 智慧局電子郵件1050901函釋（轉述自搜尋摘要）：如果畫作加入新的創意、另外成為一個創作，屬於改作；如果只是小幅修正、還沒有達到新創意的程度，屬於重製。https://topic.tipo.gov.tw/copyright-tw/cp-407-854689-7a0e0-301.html ——這個網域在本環境連不上，**原文未核對**。
- 智慧局網路篇（轉述）：用軟體把照片套成油畫、水彩效果，構圖沒有實質改變，屬於重製而不是改作。https://www.tipo.gov.tw/ct.asp?ctNode=7561&mp=1&xItem=219598 （**原文未核對**）

→ 套用到平面圖：**換配色、換線條粗細，就相當於「換濾鏡」**，構圖、牆線、比例都沒變，最可能被認定為**重製**。

**(b) 法院：色調不同不影響「實質近似」的認定。**
- 智慧財產及商業法院111年度民著訴字第80號民事判決（理律整理）：被告照著原告的照片畫成畫，法院認為「雖然原告照片與被告畫作之色調、光影有細微差異，但主要色調均相似」，二者「整體觀念與感覺」均一致，構成實質近似；「被告以繪畫方式對照片直接重複製作，構成以重製方式侵害原告對於照片的著作權」。https://www.leeandli.com/TW/NewslettersDetail/7123.htm （判決原文**未直接核對**）
- 這個案子處理的是照片，不是平面圖，但道理一樣：換媒材、換色調，不會讓實質近似消失。

**(c) 判斷侵權用的「接觸＋實質近似」。**
- 最高法院81年度台上字第3063號判決常被引用：主張抄襲的一方要證明對方「接觸」過原著作，而且兩者「實質近似」（智慧局整理 https://www.tipo.gov.tw/tw/tipo1/209-21673.html ；判決原文**未核對**）。
- 智慧財產法院100年度刑智上訴字第39號等判決：相似程度越高，接觸的證明門檻越低；相似到難以想像沒有接觸（striking similarity）時，可以推定有接觸（轉述自東海大學智財網 https://ipr.thu.edu.tw/?p=902 、理律 https://www.leeandli.com/TW/Newsletters/6117.htm ；判決原文**未核對**）。
- 智慧財產法院99年度民著訴字第36號（轉述）：寫實或事實性的作品雷同的可能性比較高，要有更多相似才會構成實質近似，受保護的程度比較低。
- **套用到描圖**：描圖一定有接觸（原圖就是底圖），牆線比例又幾乎一樣，兩個要件都很容易成立。描圖檔、圖層、AI 對話紀錄，打官司時都可能被調出來。

**(d) 建築圖、設計圖在台灣的定位。**
- 內政部81年著作內容例示：建築著作「包括建築設計圖、建築模型、建築物」；圖形著作「包括地圖、圖表、科技或工程設計圖」（見前一份研究 B1）。
- 室內設計圖要歸為圖形著作還是建築著作，法院看法不一致：智慧財產法院104年度民著訴字第32號、108年度民著訴字第124號認定室內平面設計圖是圖形著作，依圖施工只是「實施」。最高法院110年度台上字第3615號刑事判決則維持了二審「室內設計圖屬建築設計圖」的見解（理律 https://www.leeandli.com/TW/Newsletters/7354.htm ；聖島 https://www.saint-island.com.tw/Tw/News/News_Info.aspx?IT=News_1&CID=266&ID=12185 ；著作權筆記 https://www.copyrightnote.org/ArticleContent.aspx?ID=6&aid=2973 ；判決原文都**未核對**）。
- 這個爭議講的是「依圖**施工**」算不算重製。**我們的情況是「圖→圖」（平面複製到平面）**，不論那張圖被歸為圖形著作或建築著作，平面複製到平面都是典型的重製，沒有「實施」的空間可以主張。

**(e) 台灣有沒有房仲或建商之間抄平面圖的判決？**
- 這次搜尋**沒有找到**台灣法院針對「仲介或建商描繪、轉載他人銷售平面圖或格局圖」的判決，也沒有找到智慧局針對「格局圖重繪」的專門函釋。**未查證**：建議用司法院裁判書系統（https://judgment.judicial.gov.tw/ ）以「平面圖 & 重製」「格局圖 & 著作權」「銷售海報 & 平面圖」查全文。
- 沒有判決**不代表**可以做。比較可能的原因是建商很少為一張圖去告人，多半先發存證信函或要求下架；而且一般網站盜圖的判決，結果幾乎都是侵權。

### 3. 原創性低、保護「薄」：有幫助，但幫不到描圖

- 住宅平面受到法規、結構、柱位、管道間、採光和常見格局的限制，可以自由選擇的空間小，所以**原創性門檻雖然過得了，保護範圍很窄（thin protection）**。
- **日本**知財高裁平成27年（2015）5月25日判決（公寓建築設計圖案）：法院認為建築圖的畫法遵循共通的製圖規則，「作圖上的表現方法的選擇余地幾乎沒有」；具體的房間形狀與組合有「極其有限」的創作性，所以只保護到**接近完全照抄（デッドコピー）的程度**。柱位、住戶配置、陽台形式、電梯樓梯位置等主張，被認定為設計條件或思想。https://www.gojo-partners.com/column-ps/6503/
- **美國** Home Design Services v. Turner Heritage Homes, 825 F.3d 1314（11th Cir. 2016）、Intervest v. Canterbury Estate Homes, 554 F.3d 914（11th Cir. 2008）：建築平面圖的保護是 thin，只保護標準元素的「選擇與編排」；Design Basics v. Signature Construction（7th Cir. 2021）甚至要求兩張圖「virtually identical」才構成侵權。https://law.justia.com/cases/federal/appellate-courts/ca11/15-11912/15-11912-2016-06-17.html （本次只看了摘要；美國另有 Architectural Works Copyright Protection Act 1990，跟台灣制度不同）
- **對我們的意義**：保護薄，表示「獨立畫出一樣的格局」是安全的。但薄保護防的正是 dead copy（照抄），**描圖換色恰好就是 dead copy**。保護薄這件事，只對「不看原圖、自己畫」有幫助，對描圖沒有幫助。台灣法院會不會採同樣的「薄保護」思路，**未查證**（99民著訴36 的「事實作品要求較多相似」是類似的方向）。

### 4. 第58條（公共場所的建築著作）能不能用？

第58條允許以任何方法利用「於街道、公園、建築物之外壁或其他向公眾開放之戶外場所長期展示」的建築著作，但不能以建築方式重製建築物。這條講的是**戶外看得到的建築外觀**，室內格局不是戶外展示，而且它允許的是利用**建築物本身**，不是利用建商的**圖**。**不建議依賴**；台灣有沒有實務把這條用在室內格局，**未查證**。

### 5. 實務界線

**不行（需要授權）**
1. 描圖：把原圖放在底層，在上面畫牆線（Illustrator、Figma、PowerPoint、iPad 描圖都算），換顏色、換線寬、換字型。
2. 掃描或截圖原圖，再去背、重新上色、向量化（Image Trace、Potrace）。
3. 把原圖丟進 AI（「幫我把這張平面圖重畫成簡約風」「轉成 SVG」），不論輸出看起來多不一樣。輸入就是重製，輸出跟原圖幾何相同時也是重製。
4. 用原圖量比例，照抄牆的位置、房間長寬比、柱位、管道間的形狀。
5. 保留原圖的標註、家具配置、尺寸數字、房間命名方式、圖例與版面。
6. 「先描一份，再自己改幾條線」：起點就是重製，中途的檔案就構成侵權證據。

**灰色地帶（不建議，或要謹慎處理）**
- **看過原圖再憑記憶畫**：在法律上算「有接觸」，結果如果跟原圖高度相似，很難證明是獨立創作。規避方法：只畫泡泡圖或方塊圖這種**不會跟原圖相似的抽象表現**，並保存「事實來源」的證據。
- **用建商圖查一個事實**（例如「主臥有沒有附衛浴」）：事實本身可以用，但**不要在畫圖時打開原圖**，事實要另外記錄成文字。
- **竣工圖、建物測量成果圖**：可以私下核對面積與房間數，不上網（也牽涉隱私，見前一份研究 B2）。
- **委託人提供的建商圖**：屋主擁有房子，不代表擁有那張圖的著作權，**照樣不能用**。

**可以（風險低）**
1. **從事實自己畫**：房廳衛數（實價登錄、權狀）、主建物、陽台面積（權狀、實價登錄）、方位與相鄰關係（自己到現場看、本店委託物件的現場紀錄），畫成**統一樣式的方塊圖或泡泡圖**，不照比例。
2. **本店委託物件、本店自繪的格局圖**：最安全的來源。物件下架後要去識別化（只標戶型代號），或取得原委託人同意。
3. **建商書面授權**：如果建商願意（新案或代銷合作時比較容易），要拿到書面授權，寫明可以在網站、社群、影片使用，可以修改，並註明出處；之後直接使用最省事。

**建議**：可行時，先寄信請建商或代銷書面授權；拿不到授權，就只用下面的「阿陞版示意圖」。

## 任務二：阿陞版標準戶型示意圖（製作方法）

### 1. 原則
- **輸入只用事實**，一律不讀任何圖檔：程式根本沒有讀圖的功能，從流程上就排除描圖的可能。
- **刻意抽象**：用格子上的圓角方塊表示房間的「相對位置」，**不照比例、沒有牆厚、沒有門窗弧線、沒有家具**。阿陞版每一張圖都長得一樣，跟任何建商圖的「表達」都不可能相似。
- **只標戶型代號**（A型 3房），不標棟、樓層、戶號、門牌（隱私，CLAUDE.md 與前一份研究 B2）。
- **固定兩行附註**＋資料來源＋繪製日期；範例圖右上角加紅字「範例」。
- 品牌：紅色 #C8161D 只用在頂條、入口箭頭、指北針、「範例」字樣；房間用中性灰與米色；線寬統一 2px；陽台用虛線。

### 2. 允許與禁止的輸入

| 允許 | 禁止 |
|---|---|
| 房／廳／衛數（實價登錄「建物現況格局」、權狀、本店物件） | 建商 DM、官網、接待中心平面圖（看、描、拍照、丟給 AI 都不行） |
| 主建物、陽台面積（權狀、實價登錄，換算成坪，四捨五入到 0.1） | 591、樂居、他店的格局圖、照片 |
| 方位（現場用手機羅盤、自己拍的照片、本店物件） | 竣工圖、建物測量成果圖（只能私下核對，不能當底圖） |
| 相鄰關係（自己的現場手繪草圖或文字筆記：例如「客廳接前陽台、主臥附衛浴、廚房靠後陽台」） | 任何會讓人回推到特定一戶的資料（樓層、戶號、門牌） |
| 建商的**書面授權**（有授權時才可以參考它的圖） | |

程式拒絕產圖的情況（已測試，`bad.json` 會回報三項錯誤）：
- 有 `floor`／`unit_no`／`address`／門牌等欄位；

### 4. 產生器（Python，只用標準函式庫，111 行）

檔案：`/tmp/claude-0/floorplan/gen_floorplan.py`　用法：`python3 gen_floorplan.py unit.json out.svg`

```python
#!/usr/bin/env python3
"""阿陞版標準戶型示意圖產生器（只用標準函式庫）。
用法：python3 gen_floorplan.py unit.json out.svg
輸入只能是事實資料（房廳衛數、面積、方位、自己現場畫的相鄰關係），不讀任何圖檔。"""
import json, sys, math
from xml.sax.saxutils import escape as esc

CELL, PAD, TOP, BOTTOM = 52, 40, 96, 128      # 一格 52px；格子是「相對位置」不是尺寸
RED, INK, LINE = "#C8161D", "#222222", "#555555"
FILL = {"living": "#F4F1EC", "dining": "#F4F1EC", "bed": "#ECECEC", "kitchen": "#E6EAED",
        "bath": "#E6EAED", "balcony": "#FFFFFF", "other": "#F7F7F7"}
CAP1 = "格局示意，非依比例繪製，僅供參考；實際以現場、權狀及使用執照為準"
CAP2 = "本圖為本店依公開資料與現場勘查自行繪製之示意圖，非建商原始圖面"
FORBIDDEN_KEYS = {"floor", "unit_no", "address", "door_no", "樓層", "門牌", "戶號"}
OK_SOURCES = {"權狀", "實價登錄", "現場勘查", "本店委託物件", "建商書面授權"}
BAD_SOURCES = {"建商平面圖", "591", "他店格局圖", "竣工圖", "測量成果圖"}

def check(u):
    errs = [f"不可有欄位 {k}（隱私）" for k in FORBIDDEN_KEYS if k in u]
    for s in u.get("sources", []):
        if s["type"] in BAD_SOURCES or s["type"] not in OK_SOURCES:
            errs.append(f"來源 {s['type']} 不在允許清單")
        if not s.get("evidence"):
            errs.append(f"來源 {s['type']} 缺佐證檔名")
    if not u.get("sources"):
        errs.append("沒有填資料來源")
    occ = {}
    for r in u["rooms"]:
        x, y, w, h = r["cell"]
        if x < 0 or y < 0 or x + w > u["grid"][0] or y + h > u["grid"][1]:
            errs.append(f"{r['name']} 超出格子範圍")
        for i in range(x, x + w):
            for j in range(y, y + h):
                if (i, j) in occ:
                    errs.append(f"{r['name']} 與 {occ[(i, j)]} 重疊")
                occ[(i, j)] = r["name"]
    c = u["counts"]
    beds = sum(1 for r in u["rooms"] if r["type"] == "bed")
    baths = sum(1 for r in u["rooms"] if r["type"] == "bath")
    if (beds, baths) != (c["房"], c["衛"]):
        errs.append(f"房間數 {beds}房{baths}衛 與 counts {c['房']}房{c['衛']}衛 不符")
    return sorted(set(errs))

def room_svg(r):
    x, y, w, h = r["cell"]
    px, py, pw, ph = PAD + x * CELL + 3, TOP + y * CELL + 3, w * CELL - 6, h * CELL - 6
    dash = ' stroke-dasharray="6 4"' if r["type"] == "balcony" else ""
    out = [f'<rect x="{px}" y="{py}" width="{pw}" height="{ph}" rx="10" fill="{FILL.get(r["type"], FILL["other"])}" '
           f'stroke="{LINE}" stroke-width="2"{dash}/>']
    cx, cy = px + pw / 2, py + ph / 2
    one_line = h == 1 and r.get("note")          # 矮房間：備註併在同一行
    label = f'{r["name"]}<tspan font-size="11" font-weight="400" fill="#777">（{esc(r["note"])}）</tspan>' if one_line else esc(r["name"])
    out.append(f'<text x="{cx}" y="{cy + 5}" font-size="16" font-weight="700" fill="{INK}" text-anchor="middle">{label}</text>')
    if r.get("note") and not one_line:
        out.append(f'<text x="{cx}" y="{cy + 24}" font-size="11" fill="#777" text-anchor="middle">{esc(r["note"])}</text>')
    return out

def entrance_svg(e):
    side, pos = e["side"], e["pos"]          # pos = 第幾格（從 0 起），箭頭畫在該格中點
    gx, gy = U["grid"]
    if side in ("S", "N"):
        x = PAD + (pos + .5) * CELL; y = TOP + (gy * CELL if side == "S" else 0)
        d = 1 if side == "S" else -1
        pts = f"{x},{y + 4*d} {x-9},{y + 20*d} {x+9},{y + 20*d}"; tx, ty = x, y + 36 * d + (4 if d > 0 else 0)
    else:
        y = TOP + (pos + .5) * CELL; x = PAD + (gx * CELL if side == "E" else 0)
        d = 1 if side == "E" else -1
        pts = f"{x + 4*d},{y} {x + 20*d},{y-9} {x + 20*d},{y+9}"; tx, ty = x + 34 * d, y + 5
    return [f'<polygon points="{pts}" fill="{RED}"/>',
            f'<text x="{tx}" y="{ty}" font-size="13" font-weight="700" fill="{RED}" text-anchor="middle">入口</text>']

def north_svg(deg, cx, cy):
    t = f'rotate({deg} {cx} {cy})'
    return [f'<circle cx="{cx}" cy="{cy}" r="22" fill="#fff" stroke="{RED}" stroke-width="2"/>',
            f'<g transform="{t}"><polygon points="{cx},{cy-17} {cx-7},{cy+8} {cx},{cy+3} {cx+7},{cy+8}" fill="{RED}"/>',
            f'</g>', f'<text x="{cx + 34*math.sin(math.radians(deg))}" y="{cy - 34*math.cos(math.radians(deg)) + 4}" '
            f'font-size="12" font-weight="700" fill="{RED}" text-anchor="middle">N</text>']

def render(u):
    gx, gy = u["grid"]
    W = max(PAD * 2 + gx * CELL + 90, 560); H = TOP + gy * CELL + BOTTOM
    c, a = u["counts"], u.get("areas_ping", {})
    head = f'{u["type_label"]}｜{c["房"]}房{c["廳"]}廳{c["衛"]}衛'
    sub = "　".join(f"{k}約 {v} 坪" for k, v in a.items())
    s = [f'<svg xmlns="http://www.w3.org/2000/svg" width="{W}" height="{H}" viewBox="0 0 {W} {H}" '
         f'font-family="Noto Sans TC, PingFang TC, Microsoft JhengHei, WenQuanYi Zen Hei, sans-serif">',
         f'<rect width="{W}" height="{H}" fill="#fff"/>', f'<rect x="0" y="0" width="{W}" height="6" fill="{RED}"/>',
         f'<text x="{PAD}" y="42" font-size="22" font-weight="700" fill="{INK}">{esc(u["community"])}　{esc(head)}</text>',
         f'<text x="{PAD}" y="66" font-size="13" fill="#555">{esc(sub)}</text>']
    if u.get("sample"):
        s.append(f'<text x="{W - PAD}" y="42" font-size="18" font-weight="700" fill="{RED}" text-anchor="end">範例</text>')
    for r in u["rooms"]:
        s += room_svg(r)
    s += entrance_svg(u["entrance"])
    s += north_svg(u.get("north_deg", 0), PAD + gx * CELL + 52, TOP + 30)
    srcs = "、".join(x["type"] for x in u["sources"])
    y0 = TOP + gy * CELL + 70
    s += [f'<line x1="{PAD}" y1="{y0 - 18}" x2="{W - PAD}" y2="{y0 - 18}" stroke="#ddd"/>',
          f'<text x="{PAD}" y="{y0}" font-size="12" fill="{INK}">{CAP1}</text>',
          f'<text x="{PAD}" y="{y0 + 18}" font-size="12" fill="{INK}">{CAP2}</text>',
          f'<text x="{PAD}" y="{y0 + 36}" font-size="11" fill="#777">資料來源：{esc(srcs)}｜繪製 {esc(u["drawn_on"])}</text>',
          '</svg>']
    return "\n".join(s)

if __name__ == "__main__":
    U = json.load(open(sys.argv[1], encoding="utf-8"))
    problems = check(U)
    if problems:
        sys.exit("不產圖：\n" + "\n".join(problems))
    open(sys.argv[2], "w", encoding="utf-8").write(render(U))
    print("OK", sys.argv[2])
```

### 5. 範例輸出

- PNG：`/tmp/claude-0/floorplan/example.png`（已開圖檢查：標題、房間標籤、陽台虛線、入口紅箭頭、指北針（北朝下）、兩行附註、來源與日期都正常顯示，沒有文字重疊）
- 內容是**虛構範例**（「範例社區（虛構）」A型 3房2廳2衛），右上角有紅字「範例」。

**上線注意**
- SVG 用的是系統字型（Noto Sans TC → PingFang → 微軟正黑 → 文泉驛）。用 `<img>` 嵌入時，各裝置字型會有一點差異。要統一的話，改成 inline SVG，讓它沿用頁面的字型。
- 寬度約 560 到 600px，靠 viewBox 縮放，手機寬度不會出現橫向捲動。
- 放在社區頁時，頁首、頁尾的法規揭露照舊（CLAUDE.md 法遵段）。圖上的面積只寫「約 X 坪」，不寫金額、單價、屋齡。

### 6. 作業流程檢查表

**A. 蒐集（業務或阿陞本人）**
- [ ] 確認這個戶型的房廳衛數：實價登錄（同社區、同一種格局至少 1 筆以上；跟戶型分布表同一批資料），或本店物件的權狀。存 CSV 或權狀影本（遮蔽個資），檔名寫進 `sources.evidence`。
- [ ] 主建物、陽台面積：權狀或實價登錄，換算成坪，四捨五入到 0.1。同一個戶型有幾筆數字的話，取最常見的值，或寫範圍。
- [ ] 方位與相鄰關係：**由實際到現場的人**（帶看、委託物件、公設參觀）用手機羅盤記錄座向，**手繪草圖**只畫方塊和相鄰關係。拍照存檔（只拍自己的草圖，不拍住戶物品）。
- [ ] **畫圖的電腦或手機上不開任何建商圖、591 圖**；也不把那些圖傳給 AI。

**B. 製作**
- [ ] 依手繪草圖填 JSON 的 `rooms`（格子座標），執行產生器；程式擋下就修正資料，不手動改 SVG 繞過檢查。
- [ ] 產生 PNG，自己檢查標籤和方位。
- [ ] 把 JSON、SVG、PNG、證據檔放在同一個資料夾（建議 `floorplans/<社區>/<戶型>/`）。這個資料夾**留著當作「獨立創作」的證據**：證明資料來源是事實，不是原圖。

**C. 核可（林津陞本人）**
- [ ] 林津陞看過圖、JSON 和證據後，在 JSON 加 `"approved_by": "林津陞", "approved_on": "YYYY-MM-DD"`（建議之後在產生器加檢查：沒有這兩個欄位就只能產生「草稿」浮水印）。
- [ ] 核對：沒有樓層、戶號；附註兩行都在；沒有金額或禁用詞（realtor-ad-compliance）；來源欄沒有出現禁止的來源。

**D. 發布與維護**
- [ ] 經由 property-deck 指揮艙發布（不要手改網站的 index、LD 區塊，見 CLAUDE.md）。
- [ ] 如果有人反映跟某張建商圖太像，或收到建商來信：先下架，再依證據資料夾說明繪製過程，請林津陞決定要不要改畫或取得授權。
- [ ] 本店委託物件的圖：物件下架後，改用去識別化的戶型示意，或取得委託人同意後再保留。
