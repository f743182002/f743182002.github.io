# 社區頁新增「充電樁」與「平面圖／戶型」：法規研究與資料設計

- 對象：林津陞（全國不動產板橋加盟店）banqiaoasheng.com 社區分析頁、商圈地圖（`data/communities.json`）
- 研究日：2026-11-04（民國115年11月4日）
- 範圍：只做研究與設計，沒有改動 repo
- 標示方式：每一項法規說法都附來源網址。查不到原文或無法確認的，標「**未查證**」。新聞或業者文章只當作線索，不當作法源。

## 摘要（先看這段）

1. **公寓大廈管理條例目前沒有「充電樁專條」**。全國法規資料庫顯示，最新修正日是 111/05/11，條文裡沒有「充電」或「電動車」。行政院版修正草案的內容是：裝設前要做用電安全評估、投保公共意外責任保險、降低臨時區權會的召開門檻。這份草案 112/7/13 送行政院，之後一直沒有三讀的紀錄。所以現在仍照一般條文處理：
   - 第6條第1項第4款：使用共用部分配管，要經管理委員會同意。
   - 第11條：共用部分的重大修繕或改良，要經區分所有權人會議決議。
   - 第36條：管委會要執行區權會的決議。

   營建署 2022 年明白說過，修法方向是「尊重社區自治……並非不得拒絕」。**所以網站上不能寫「管委會不能拒絕」或「一定可以裝」。**
2. **新建案預留的規定分兩層，要分開寫**：
   - 全國：建築技術規則建築設計施工編第62條第4款規定，**108/7/1 起申請建造執照**的新建物，停車空間要「預留供電動車輛充電相關設備及裝置之**裝設空間**」。這條只要求預留空間，沒有要求配好管線。
   - 新北：新北市工務局 111/6/13 函附的會議紀錄寫明，**集合住宅自 111/3/1 起，停車空間要按實設車位數全數留設充電設施管線**。台電也公告，111/3/1 起新建集合住宅的充電樁要採「專設一戶」供電。這兩條規定的基準日，是看建照掛號日、核發日，還是用電申請日，**未查證**。
3. **平面圖**：建商銷售平面圖、591／樂居／他店的格局圖、竣工圖，都可能是受保護的「建築著作」或「圖形著作」（著作權法第5條，內政部 81 年著作內容例示）。智慧局的見解是，未經同意重製就是侵權，即使是為了別的用途也一樣。在網站上刊出，還涉及「公開傳輸」。竣工圖在新北要附所有權證明才能申請影印。**可以公開放的只有**：(a) 本店經手、本店自己繪製（或取得授權）的物件格局圖；(b) 阿陞自己依實價登錄或現場丈量重新繪製、不描摹他人圖面的簡化示意圖。另外有一個完全不用圖的做法：**用實價登錄的「建物現況格局-房／廳／衛」和「主建物面積」做社區戶型分布表**。這是最安全、最快能上線的方式。
4. **建議資料結構**：`communities.json` 每個社區加 `ev`、`layouts`、`plans` 三組欄位，所有值都要先進 facts_verified.json，再寫進 communities.json。

**小結（可以寫進網站的說法）**：住戶在自己的（約定專用）車位裝充電設備，只要管線經過共用部分，就要先經管委會同意。如果涉及共用部分的重大改良，例如社區統一設置線槽或向台電申請專設電表，要依區權會決議。現行法沒有「管委會不得拒絕」的規定。

#### (3) 經濟部、台電的技術與用電規定

- **用戶用電設備裝置規則**：「電動車輛充電系統」專節是第396-1～396-17條。新北指引第25頁和立法院研析都有引用。條文原文**未逐條核對**，全國法規資料庫可以查。
- **兩種供電方式**（台電簡報第11～18頁）：
  - **表後接電**：從自家電表拉線。申請比較方便，但用的是公共範圍，「較有爭議」，多戶共用表前開關時有跳電、安全的疑慮。
  - **專設一戶**：由管委會向台電申請充電專用電表，整體規劃電纜架或線槽，可以選用電動車專用電價，並導入 EMS（能源管理系統）。
- **電動車充換電設施電價**：適用於合計設備容量或契約容量 20 瓩以上、未滿 100 瓩。「集合住宅建築物附設停車場之充電設施採專設一戶或分層設戶者，不受前述最低容量限制」。來源是台電 PDF https://www.taipower.com.tw/media/jx3fpc3g/ 。這次抓取 PDF 回 503，內容取自搜尋摘要，**請再開原檔核對**。
- **台電施工分工**（台電簡報第10頁）：用戶委託電器承裝業或電機技師做內線評估與施工、報竣工，台電檢驗送電，必要時加裝變壓器。新北指引第16頁補充：要由合格電器承裝業或電機技師規劃，並向台電申請用電評估；契約容量超約是罰款，不是跳電。
- **契約容量 100 瓩以上**：台電建議設置 EMS（彰化縣指引引用的台電說明，國土署網站 https://www.nlma.gov.tw/uploads/files/6f57425072e79dd85157dc215c4ebb44.pdf ，**未逐字核對**）。

### A2. 社區分類：標籤、證據門檻與給買方的說法

設計原則：
- 只說「有什麼依據」，不說「能不能裝」。
- 一個社區可以同時有「法定基準」和「現況」兩類標籤。
- 沒有證據就是「未查證」。

**建照日期怎麼對應法規**（新北市建管便民網的使照存根和建照存根，pipeline 已經在用）：

1. 使照存根和新北開放資料「新北市建築執照存查」有「原建造(雜項)執照字號」欄。新北開放資料欄位有 `發照日期`、`領照日期`、`開工日期`，**沒有建照申請（掛號）日期欄位**（https://data.gov.tw/dataset/123639 ）。
2. 判斷規則（保守做法）：
   - **使照竣工或建照核發在 108/7/1 以前** → 建照申請一定也在 108/7/1 以前 → `existing_needs_approval`。目前地圖上已發布的社區多半是民國84～105年使照，都屬這一類。
   - **建照核發在 108/7/1 以後** → 申請日可能在之前也可能在之後 → 要查到建照存根上的掛號（申請）日期，才能標 `law_space_108`。查不到就標 `unverified`，並註明「建照於108/7/1後核發，申請日待查」。建照存根有沒有掛號日期，**未查證**，請在建管便民網實際確認。
   - **新北集合住宅、建照日期在 111/3/1 以後** → 可以標 `ntpc_conduit_111`。因為基準日的定義**未查證**，建議採「**核發日 ≥ 111/3/1**」這個保守門檻；如果是 111/3/1 以前掛號、以後核發，就標 `law_space_108` 並註記待查。
   - 變更設計不會改變原建照的申請日。所以要用原建照字號查，不要用變更案的日期。

## B. 平面圖／戶型圖

### B1. 著作權與取得限制

**法律基礎**
- 著作權法第5條例示著作，包括「六、圖形著作」「九、建築著作」：https://law.moj.gov.tw/LawClass/LawAll.aspx?pcode=J0070017
- 內政部 81/6/10《著作權法第五條第一項各款著作內容例示》：
  - 建築著作「包括建築設計圖、建築模型、建築物及其他之建築著作」。
  - 圖形著作「包括地圖、圖表、科技或工程設計圖及其他之圖形著作」。
  - 來源：rootlaw 轉載 https://www.rootlaw.com.tw/LetterContent.aspx?LCode=13&SOID=149561 ，全國法規資料庫原文**未直接開啟核對**。
- 第10條之1：保護只及於「表達」，不及於「思想、程序、製程、系統、操作方法、概念、原理、發現」。所以「3房2廳2衛、主建物約24坪」這類**事實資訊不受保護**，但「某張圖的畫法」受保護。
- 第9條：法律、命令、公文不受保護。竣工圖是建築師的設計圖，不是「公文」，不會因為存在建管機關就變成公共財。這是依條文的推論，沒有找到智慧局對竣工圖的專門解釋，**未查證**。
- 智慧局著作權 Q&A：「工程第二原圖若屬著作，就該著作予以重製（即複製），除符合著作權法合理使用規定的情形外，若未經著作財產權人的同意，即屬違反著作權法的行為，縱其重製之目的係供他人製作模型亦同。」https://www.tipo.gov.tw/tw/copyright/766-4888.html
- 實務上，設計圖兼具圖形與建築著作性質的見解，最高法院110年度台上字第3615號刑事判決予以維持（轉述自理律、聖島文章：https://www.leeandli.com/TW/Newsletters/7354.htm 、https://www.saint-island.com.tw/Tw/News/News_Info.aspx?IT=News_1&CID=266&ID=12185 ）。判決原文**未直接核對**。
- 網站使用他人圖片構成重製與公開傳輸：智慧財產及商業法院114年度民著訴字第22號（攝影圖片案，轉述自 lawplayer）https://lawplayer.com/judgment/IPCV,114,%E6%B0%91%E8%91%97%E8%A8%B4,22,20250924,1_24fd2d2ee62975aa7e21782747a33f766d251d2d
- 合理引用（第52條）要有「報導、評論、教學、研究或其他正當目的之必要，在合理範圍內」。商業招攬性質的社區頁整張轉貼平面圖，很難主張合理引用。這是法律評估，**沒有找到直接判決**。

**各類來源的判斷**

| 來源 | 可否公開放網站 | 理由與條件 |
|---|---|---|
| 建商銷售平面圖（DM、官網、接待中心） | **不建議**（除非取得建商書面授權） | 建商或建築師的圖形或建築著作。預售屋廣告平面圖依法是契約的一部分，屬建商的銷售資料，授權範圍不會包含他店轉載 |
| 591、樂居、他店的格局圖或照片 | **不可** | 他人著作，重製加公開傳輸。平台使用條款的細節**未查證**，但不影響著作權結論 |
| 使照竣工圖（建管單位影印） | **不可公開** | 新北申請影印要附建物所有權人的權利證明（或管委會報備證明、買賣或租賃契約等），見工務局問答 https://www.publicwork.ntpc.gov.tw/home.jsp?id=2d77083c299dfb04&act=be4f48068b2b0031&dataserno=80f2dc1b20051eeafa3268e450487a21 。著作權屬建築師或起造人，圖上也可能有個別戶的資訊。只能私下給委託人或買方參考，不上網 |
| 建物測量成果圖（地政） | **不建議公開** | 臺北市地政局說成果圖謄本「任何人均可申請……無資格限制」https://land.gov.taipei/News_Content.aspx?n=8BF117349E1FE052&s=6945C7AF5BDAD729 （新北是否相同，**未查證**）。但這份圖對應**特定門牌、特定樓層**，公開等於揭露特定住戶的房屋，牽涉隱私（見 B2）。著作權歸屬（地政機關製作是否算公文）**未查證**。可以私下用來核對面積 |
| **本店經手物件、本店繪製的格局圖** | **可以**（條件見右） | 著作權歸繪製人或公司。如果是外包繪製，要確認契約約定權利或授權；全國不動產總部或加盟店間的權利約定**未查證**，請確認。另外：(1) 物件成交、下架後，社區頁還要繼續放，應該取得原委託人同意，或去掉樓層、門牌的識別資訊；(2) 標「格局示意，非依比例繪製」。現有 S21140123 的 config 已有「格局示意，非實測，家具為示意，實際以現場為準」 |
| **阿陞自行重繪的簡化示意圖** | **可以**（條件見右） | 依自己現場丈量、權狀登記面積、實價登錄房廳衛數**重新繪製**，**不可以拿建商圖或他店圖描摹、套底**（描摹仍可能是重製或改作）。用 AI 生成的也一樣，不能拿他人圖面當輸入。要標「示意」 |

### B2. 隱私

- 個人資料保護法第2條：個人資料包括「其他得以直接或間接方式識別該個人之資料」（https://law.moj.gov.tw/LawClass/LawAll.aspx?pcode=I0050021 ）。「某社區＋某棟＋某樓＋格局圖」再加上實價登錄或居住者的資訊，有可能間接識別住戶。
- 原則：
  1. 社區頁只放**戶型類別**（例如「A 型：3房」），**不標樓層、門牌、棟別戶號**。
  2. 本店物件頁（S編號）照 591 刊登原則**隱藏門號**。物件下架後，格局圖要從社區頁移除，或改成去識別化的戶型示意。
  3. 實價登錄統計用**彙總表**呈現。同一格的筆數少於 3 筆就併入「其他」，避免反推個別交易。這個門檻是建議值，不是法規要求。
  4. 照片不拍住戶物品、名牌、車牌。

### B3. 建議做法（由安全到需授權）

1. **第一層（立刻可做、不用圖）**：用實價登錄做「戶型分布表」（見 B4）。
2. **第二層（有本店物件時）**：放本店自繪格局圖，去識別化，只標戶型代號。
3. **第三層（選用）**：阿陞自己重繪的戶型簡圖（SVG），只畫房間相對位置，不標尺寸。
4. **不做**：建商圖、他店圖、竣工圖、成果圖上網。

**必備附註文字**
- 圖：「格局示意，非依比例繪製，僅供參考；實際以現場、權狀及使用執照為準。」
- AI 或自繪：「本圖為本店依公開資料與現場丈量自行繪製之示意圖，非建商原始圖面。」AI 輔助的話加「AI 輔助繪製」。
- 表：「戶型統計依內政部實價登錄申報之『建物現況格局』與『主建物面積』整理，為申報資料，可能與現況不同；不代表個別房屋。」

### B4. 實價登錄做戶型分布（不用任何圖）

- 公開資料有這些欄位：「建物現況格局-房」「建物現況格局-廳」「建物現況格局-衛」「建物現況格局-隔間」「主建物面積」「附屬建物面積」「陽台面積」「建物移轉總面積平方公尺」「移轉層次」「總樓層數」「建物型態」「主要用途」「車位類別」（data.gov.tw 實價登錄 Open Data 欄位說明，例：https://data.gov.tw/dataset/171701 ；來源 https://plvr.land.moi.gov.tw/ ）。
- 做法（沿用 pipeline 已經在用的社區門牌查詢）：
  1. 用和社區「實價登錄 N 筆」同一批資料（同樣排除特殊交易）。
  2. 篩選：`主要用途` 含「住」，`建物型態` 為住宅大樓或華廈；排除店面、辦公、純車位交易。新巨蛋這類混合使用社區特別要篩。
  3. 依「房」數分組：0（開放格局或套房，看隔間）、1、2、3、4+。每組算筆數，以及**主建物面積**的範圍（平方公尺 × 0.3025 換算成坪，取 P10～P90 或 min～max，四捨五入到 0.5 坪）。
  4. 同一戶重複成交只算一次（用門牌＋移轉層次去重），才代表「戶型」而不是「交易」。
  5. 筆數少於 3 的組併入「其他」。
- 不顯示任何金額、單價。不顯示建築完成年。
- 限制（要寫在附註）：格局是申報人填的現況（可能是改隔間後的格局）；只涵蓋有成交的戶；預售屋資料（如果有用）另外標示。
